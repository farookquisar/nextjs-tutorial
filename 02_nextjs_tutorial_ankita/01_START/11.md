### 🎯 Part 1: The Default Behavior

#### **Everything is a Server Component by Default**

**Key Concept:**

> In Next.js App Router, **every component is a Server Component by default** unless you explicitly opt into Client Components.

**What this means:**

```typescript
// This is a Server Component (default)
export default function MyComponent() {
	return <div>Hello</div>;
}
```

**No special directive needed:**

- Just write a normal React component
- It automatically runs on the server
- Rendered to HTML before reaching browser
- Fast and SEO-friendly

---

### 🖥️ Part 2: Server Components Deep Dive

#### **What are Server Components?**

**Definition:**

> Server Components are React components that render exclusively on the server and send HTML to the browser.

---

#### **Characteristics of Server Components:**

**1. Rendered on the Server**

```typescript
// This runs on the server
export default async function ProductList() {
	// This fetch happens on the server
	const products = await fetch("https://api.example.com/products");
	const data = await products.json();

	return (
		<div>
			{data.map((product) => (
				<div key={product.id}>{product.name}</div>
			))}
		</div>
	);
}
```

**What happens:**

- Component executes on server
- Data fetched on server
- HTML generated on server
- HTML sent to browser
- No JavaScript needed for this component

---

**2. Don't Re-render**

```typescript
// Server Component - renders once on server
export default function StaticContent() {
	const timestamp = new Date().toISOString();

	return <div>Rendered at: {timestamp}</div>;
}
```

**Behavior:**

- Renders once on the server
- Timestamp is fixed (doesn't update)
- No re-rendering in browser
- Static HTML

---

**3. Not Included in Browser Bundle**

```typescript
// Server Component
import { someHeavyLibrary } from "heavy-library"; // 500KB

export default function ServerComponent() {
	const result = someHeavyLibrary.process();
	return <div>{result}</div>;
}
```

**Bundle impact:**

- ✅ Library runs on server
- ✅ NOT sent to browser
- ✅ Zero impact on bundle size
- ✅ Faster page loads

---

**4. Can Store API Keys Safely**

```typescript
// Server Component - SAFE
export default async function SecureComponent() {
	// This API key is NEVER exposed to browser
	const apiKey = process.env.SECRET_API_KEY;

	const data = await fetch("https://api.example.com/data", {
		headers: {
			Authorization: `Bearer ${apiKey}`,
		},
	});

	return <div>{/* render data */}</div>;
}
```

**Security:**

- ✅ API keys stay on server
- ✅ Never exposed to browser
- ✅ Safe from client-side inspection
- ✅ Secure by default

---

**5. React Server Component Stream**

**What is it?**

> A special format that React uses to stream server-rendered components to the browser.

**How it works:**

```
Server Component
    ↓
Renders to RSC Stream (special format)
    ↓
Sent to browser
    ↓
React reconstructs component tree
    ↓
Displays to user
```

**Key points:**

- Not JSON (special React format)
- Optimized for streaming
- Efficient data transfer
- Enables progressive rendering

---

**6. Cannot Pass Functions as Props**

**❌ This doesn't work:**

```typescript
// Server Component
export default function ServerComponent() {
	const handleClick = () => {
		console.log("clicked");
	};

	// ERROR: Can't pass function to another component
	return <ChildComponent onClick={handleClick} />;
}
```

**Why?**

- Functions can't be serialized
- Can't be sent over the network
- Server components don't have interactivity

---

**7. No Browser APIs**

**❌ This doesn't work:**

```typescript
// Server Component
export default function ServerComponent() {
	// ERROR: window is not defined on server
	const width = window.innerWidth;

	// ERROR: localStorage doesn't exist on server
	const data = localStorage.getItem("key");

	return <div>{width}</div>;
}
```

**Why?**

- Server has no `window` object
- Server has no `localStorage`
- Server has no DOM
- These are browser-only APIs

---

#### **When to Use Server Components:**

**✅ Use Server Components for:**

1. **Data Fetching**

```typescript
export default async function Products() {
	const products = await fetchProducts();
	return <ProductList products={products} />;
}
```

2. **Accessing Backend Resources**

```typescript
export default async function UserProfile() {
	const user = await db.user.findUnique({ where: { id: 1 } });
	return <Profile user={user} />;
}
```

3. **Keeping Sensitive Information on Server**

```typescript
export default async function SecureData() {
	const apiKey = process.env.SECRET_KEY;
	const data = await fetchWithKey(apiKey);
	return <Display data={data} />;
}
```

4. **Reducing Client-Side JavaScript**

```typescript
export default function HeavyComponent() {
	// Heavy processing on server
	const result = processLargeDataset();
	return <Result data={result} />;
}
```

5. **Static Content**

```typescript
export default function AboutPage() {
	return (
		<div>
			<h1>About Us</h1>
			<p>We are a company...</p>
		</div>
	);
}
```

### 💻 Part 3: Client Components Deep Dive

#### **What are Client Components?**

**Definition:**

> Client Components are React components that render in the browser and support interactivity, hooks, and browser APIs.

**How to create:**

```typescript
"use client"; // This directive makes it a Client Component

export default function ClientComponent() {
	return <div>I'm a Client Component</div>;
}
```

---

#### **The "use client" Directive:**

**Syntax:**

```typescript
"use client"; // Must be at the very top of the file

import { useState } from "react";

export default function Counter() {
	const [count, setCount] = useState(0);
	return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

**Rules:**

- ✅ Must be at the top of the file
- ✅ Must be a string literal
- ✅ Before any imports
- ✅ Marks the entire file as client-side

---

#### **Characteristics of Client Components:**

**1. Can Re-render**

```typescript
"use client";

import { useState } from "react";

export default function Counter() {
	const [count, setCount] = useState(0);

	// This component can re-render when count changes
	return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}
```

**Behavior:**

- Re-renders when state changes
- Re-renders when props change
- Interactive and dynamic
- Responds to user actions

---

**2. Included in Browser Bundle**

```typescript
"use client";

import { heavyLibrary } from "heavy-library"; // 500KB

export default function ClientComponent() {
	const result = heavyLibrary.process();
	return <div>{result}</div>;
}
```

**Bundle impact:**

- ⚠️ Library sent to browser
- ⚠️ Increases bundle size
- ⚠️ Slower initial page load
- ⚠️ Use sparingly

---

**3. Can Use React Hooks**

```typescript
"use client";

import { useState, useEffect } from "react";

export default function InteractiveComponent() {
	const [data, setData] = useState(null);

	useEffect(() => {
		fetchData().then(setData);
	}, []);

	return <div>{data}</div>;
}
```

**Available hooks:**

- ✅ `useState`
- ✅ `useEffect`
- ✅ `useContext`
- ✅ `useReducer`
- ✅ Custom hooks
- ✅ All React hooks

---

**4. Can Use Browser APIs**

```typescript
"use client";

import { useEffect, useState } from "react";

export default function WindowSize() {
	const [width, setWidth] = useState(0);

	useEffect(() => {
		// Browser API - works in Client Component
		setWidth(window.innerWidth);

		const handleResize = () => setWidth(window.innerWidth);
		window.addEventListener("resize", handleResize);

		return () => window.removeEventListener("resize", handleResize);
	}, []);

	return <div>Window width: {width}px</div>;
}
```

**Available APIs:**

- ✅ `window`
- ✅ `document`
- ✅ `localStorage`
- ✅ `sessionStorage`
- ✅ Browser events
- ✅ All browser APIs

---

**5. Can Pass Functions as Props**

```typescript
"use client";

export default function ParentComponent() {
	const handleClick = () => {
		console.log("clicked");
	};

	// ✅ This works in Client Components
	return <ChildComponent onClick={handleClick} />;
}

function ChildComponent({ onClick }) {
	return <button onClick={onClick}>Click me</button>;
}
```

---

#### **When to Use Client Components:**

**✅ Use Client Components for:**

1. **Interactivity (onClick, onChange, etc.)**

```typescript
"use client";

export default function Button() {
	return <button onClick={() => alert("Clicked!")}>Click me</button>;
}
```

2. **State Management**

```typescript
"use client";

import { useState } from "react";

export default function Form() {
	const [value, setValue] = useState("");
	return <input value={value} onChange={(e) => setValue(e.target.value)} />;
}
```

3. **Effects and Lifecycle**

```typescript
"use client";

import { useEffect } from "react";

export default function Analytics() {
	useEffect(() => {
		trackPageView();
	}, []);

	return <div>Page content</div>;
}
```

4. **Browser APIs**

```typescript
"use client";

import { useEffect } from "react";

export default function LocalStorage() {
	useEffect(() => {
		const data = localStorage.getItem("key");
		// Use data
	}, []);

	return <div>Content</div>;
}
```

5. **Custom Hooks**

```typescript
"use client";

import { useCustomHook } from "./hooks";

export default function Component() {
	const data = useCustomHook();
	return <div>{data}</div>;
}
```

### 📊 Part 4: Server vs Client Components Comparison

#### **Complete Comparison Table:**

| Feature                | Server Components | Client Components         |
| ---------------------- | ----------------- | ------------------------- |
| **Default**            | ✅ Yes            | ❌ No (need "use client") |
| **Re-rendering**       | ❌ No             | ✅ Yes                    |
| **Browser Bundle**     | ✅ Not included   | ⚠️ Included               |
| **API Keys**           | ✅ Safe to use    | ❌ Exposed                |
| **Functions as Props** | ❌ Not allowed    | ✅ Allowed                |
| **Browser APIs**       | ❌ Not available  | ✅ Available              |
| **React Hooks**        | ❌ Not allowed    | ✅ Allowed                |
| **Data Fetching**      | ✅ Excellent      | ⚠️ Possible but not ideal |
| **Interactivity**      | ❌ No             | ✅ Yes                    |
| **SEO**                | ✅ Excellent      | ⚠️ Requires hydration     |

### 🎯 Part 5: Decision Framework

#### **How to Choose:**

**Start with this question:**

> Does this component need interactivity or React hooks?

**If NO → Server Component (default)**

```typescript
// No "use client" needed
export default function StaticContent() {
	return <div>Static content</div>;
}
```

**If YES → Client Component**

```typescript
"use client";

import { useState } from "react";

export default function InteractiveContent() {
	const [count, setCount] = useState(0);
	return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

---

#### **Decision Tree:**

```
Does component need:
├─ User interaction (onClick, onChange)?
│  └─ YES → Client Component
├─ React hooks (useState, useEffect)?
│  └─ YES → Client Component
├─ Browser APIs (window, localStorage)?
│  └─ YES → Client Component
├─ Real-time updates?
│  └─ YES → Client Component
└─ None of the above?
   └─ Server Component (default)
```

### 🧪 Part 6: Practical Examples

#### **Example 1: Static Product Card (Server Component)**

```typescript
// app/components/ProductCard.tsx
// No "use client" - Server Component by default

interface Product {
	id: string;
	name: string;
	price: number;
}

export default function ProductCard({ product }: { product: Product }) {
	return (
		<div>
			<h2>{product.name}</h2>
			<p>${product.price}</p>
		</div>
	);
}
```

**Why Server Component?**

- ✅ No interactivity needed
- ✅ Just displays data
- ✅ Can be static HTML
- ✅ Better performance

---

#### **Example 2: Interactive Button (Client Component)**

```typescript
// app/components/AddToCartButton.tsx
"use client"; // Client Component

import { useState } from "react";

export default function AddToCartButton({ productId }: { productId: string }) {
	const [isAdding, setIsAdding] = useState(false);

	const handleClick = async () => {
		setIsAdding(true);
		await addToCart(productId);
		setIsAdding(false);
	};

	return (
		<button onClick={handleClick} disabled={isAdding}>
			{isAdding ? "Adding..." : "Add to Cart"}
		</button>
	);
}
```

**Why Client Component?**

- ✅ Needs onClick handler
- ✅ Uses useState hook
- ✅ Interactive behavior
- ✅ Must run in browser

---

#### **Example 3: Combining Both**

```typescript
// app/products/[id]/page.tsx
// Server Component (default)

import ProductCard from "@/components/ProductCard"; // Server Component
import AddToCartButton from "@/components/AddToCartButton"; // Client Component

export default async function ProductPage({
	params,
}: {
	params: { id: string };
}) {
	// Fetch on server
	const product = await fetchProduct(params.id);

	return (
		<div>
			{/* Server Component - static display */}
			<ProductCard product={product} />

			{/* Client Component - interactive button */}
			<AddToCartButton productId={product.id} />
		</div>
	);
}
```

**Best of both worlds:**

- ✅ Server Component for static content
- ✅ Client Component for interactivity
- ✅ Minimal JavaScript to browser
- ✅ Optimal performance

### 💡 Part 7: Common Patterns

#### **Pattern 1: Server Component with Client Island**

```typescript
// Server Component (page)
export default async function Page() {
	const data = await fetchData();

	return (
		<div>
			{/* Server-rendered content */}
			<Header />
			<StaticContent data={data} />

			{/* Client Component "island" */}
			<InteractiveWidget />

			{/* More server-rendered content */}
			<Footer />
		</div>
	);
}
```

**Concept:**

- Most of page is server-rendered
- Small "islands" of interactivity
- Minimal JavaScript
- Best performance

---

#### **Pattern 2: Client Wrapper for Third-Party Libraries**

```typescript
// app/components/Map.tsx
"use client";

import { MapLibrary } from "map-library";

export default function Map({ location }) {
	return <MapLibrary location={location} />;
}
```

**Usage in Server Component:**

```typescript
// Server Component
import Map from "@/components/Map";

export default function LocationPage() {
	return (
		<div>
			<h1>Our Location</h1>
			<Map location={{ lat: 40, lng: -74 }} />
		</div>
	);
}
```

---

#### **Pattern 3: Separate Data Fetching from Interactivity**

```typescript
// Server Component - fetches data
export default async function ProductsPage() {
	const products = await fetchProducts();

	return <ProductList products={products} />;
}

// Client Component - handles interactivity
("use client");

export function ProductList({ products }) {
	const [filter, setFilter] = useState("");

	const filtered = products.filter((p) => p.name.includes(filter));

	return (
		<div>
			<input value={filter} onChange={(e) => setFilter(e.target.value)} />
			{filtered.map((p) => (
				<ProductCard key={p.id} product={p} />
			))}
		</div>
	);
}
```

### ⚠️ Part 8: Common Mistakes

#### **Mistake 1: Using Hooks in Server Components**

**❌ Wrong:**

```typescript
// Server Component (no "use client")
import { useState } from "react";

export default function Component() {
	const [count, setCount] = useState(0); // ERROR!
	return <div>{count}</div>;
}
```

**✅ Correct:**

```typescript
"use client"; // Add this!

import { useState } from "react";

export default function Component() {
	const [count, setCount] = useState(0); // Now it works
	return <div>{count}</div>;
}
```

---

#### **Mistake 2: Making Everything Client Components**

**❌ Wrong:**

```typescript
"use client"; // Unnecessary!

export default function StaticPage() {
	return <div>Static content</div>;
}
```

**✅ Correct:**

```typescript
// No "use client" needed for static content
export default function StaticPage() {
	return <div>Static content</div>;
}
```

---

#### **Mistake 3: Passing Server Components to Client Components**

**❌ Wrong:**

```typescript
"use client";

export default function ClientComponent({ serverComponent }) {
	return <div>{serverComponent}</div>; // Won't work as expected
}
```

**✅ Correct:**

```typescript
// Use children pattern instead
"use client";

export default function ClientComponent({ children }) {
	return <div>{children}</div>;
}

// Usage in Server Component:
<ClientComponent>
	<ServerComponent /> {/* This works! */}
</ClientComponent>;
```

### 🎯 Chapter Summary

**What You Learned:**

**1. Server Components (Default):**

- ✅ Rendered on server
- ✅ Don't re-render
- ✅ Not in browser bundle
- ✅ Can store API keys safely
- ❌ No React hooks
- ❌ No browser APIs
- ❌ No function props

**2. Client Components:**

- Require "use client" directive
- ✅ Can re-render
- ✅ Support React hooks
- ✅ Can use browser APIs
- ✅ Can pass functions as props
- ⚠️ Included in browser bundle

**3. Decision Framework:**

- Default to Server Components
- Use Client Components only when needed
- Need interactivity? → Client Component
- Need hooks? → Client Component
- Static content? → Server Component

**4. Best Practices:**

- Keep Client Components small
- Push "use client" down the tree
- Combine both for optimal performance
- Minimize JavaScript sent to browser

**Key Takeaway:**
Next.js uses a Server-first approach. Everything is a Server Component by default, which is fast and SEO-friendly. Only opt into Client Components when you need interactivity, hooks, or browser APIs. This architecture gives you the best of both worlds: performance and interactivity.
