# Chapter 12: Next.js Data Fetching

## 📚 LEARNING GUIDE

### What You'll Learn in This Chapter

**Core Concepts:**

- Three main data fetching methods in Next.js
- Static Site Generation (SSG) - fetch once at build time
- Server-Side Rendering (SSR) - fetch on every request
- Incremental Static Regeneration (ISR) - best of both worlds
- How to implement each strategy
- When to use each method
- The extended fetch API in Next.js
- Cache control options

**Key Topics Covered:**

1. **Static Site Generation (SSG)**

   - Fetch once at build time
   - Fastest option
   - Cached forever
   - Use `cache: 'force-cache'`
   - Best for: marketing pages, product lists, documentation

2. **Server-Side Rendering (SSR)**

   - Fetch on every request
   - Always fresh data
   - Use `cache: 'no-store'`
   - Best for: personalized dashboards, user-specific data, real-time content

3. **Incremental Static Regeneration (ISR)**

   - Static + periodic updates
   - Use `next: { revalidate: seconds }`
   - Best of both worlds
   - Best for: blogs, product pages, low-frequency updates

4. **Dynamic Routes**
   - Reading cookies, headers, search params
   - Automatically makes route dynamic
   - Fresh data on every request

**Learning Outcomes:**

- Understand all three data fetching strategies
- Choose the right strategy for your use case
- Implement each method correctly
- Optimize for performance and freshness
- Use the Next.js extended fetch API

## 🛠️ PRACTICAL GUIDE

### Understanding Data Fetching Strategies

---

### 🎯 Part 1: The Three Methods Overview

#### **Next.js Extended Fetch API**

**Key Concept:**

> Next.js has extended the native browser `fetch()` API with additional caching and revalidation options.

**The three strategies:**

```typescript
// 1. Static (SSG) - cache forever
fetch(url, { cache: "force-cache" });

// 2. Dynamic (SSR) - no cache
fetch(url, { cache: "no-store" });

// 3. ISR - revalidate periodically
fetch(url, { next: { revalidate: 3600 } });
```

---

### 📊 Part 2: Method 1 - Static Site Generation (SSG)

#### **What is SSG?**

**Definition:**

> Static Site Generation fetches data once at build time and caches it forever. Every user gets the same pre-rendered HTML.

---

#### **How It Works:**

```
Build Time:
  ↓
Fetch data from API
  ↓
Generate static HTML
  ↓
Cache forever
  ↓
User Request:
  ↓
Serve cached HTML (instant!)
```

---

#### **Implementation:**

```typescript
// app/products/page.tsx
export default async function ProductsPage() {
	// Static fetch - cached forever
	const res = await fetch("https://api.example.com/products", {
		cache: "force-cache", // This is actually the default
	});

	const products = await res.json();

	return (
		<div>
			{products.map((product) => (
				<div key={product.id}>{product.name}</div>
			))}
		</div>
	);
}
```

---

#### **Characteristics:**

**Performance:**

- ⚡ **Fastest possible** - pre-rendered HTML
- ⚡ Served from CDN
- ⚡ No server processing on request
- ⚡ Instant page loads

**Data Freshness:**

- ⚠️ Data is stale (from build time)
- ⚠️ Doesn't update until next build
- ⚠️ All users see same data

**When It Happens:**

- ✅ During `npm run build`
- ✅ Once per build
- ✅ Not on user requests

---

#### **When to Use SSG:**

**✅ Perfect for:**

1. **Marketing Pages**

```typescript
// app/page.tsx - Homepage
export default async function HomePage() {
	const content = await fetch("https://cms.example.com/homepage", {
		cache: "force-cache",
	});

	return <LandingPage content={content} />;
}
```

- Content doesn't change often
- Same for all users
- Needs to be fast

---

2. **Product Listings**

```typescript
// app/products/page.tsx
export default async function ProductsPage() {
	const products = await fetch("https://api.example.com/products", {
		cache: "force-cache",
	});

	return <ProductGrid products={products} />;
}
```

- Product catalog is relatively stable
- Can rebuild when products change
- Fast browsing experience

---

3. **Documentation**

```typescript
// app/docs/[slug]/page.tsx
export default async function DocPage({ params }) {
	const doc = await fetch(`https://api.example.com/docs/${params.slug}`, {
		cache: "force-cache",
	});

	return <Documentation content={doc} />;
}
```

- Documentation rarely changes
- Needs to be instantly accessible
- SEO important

---

#### **Example: Static Product List**

```typescript
// app/products/page.tsx
export default async function ProductsPage() {
	// Fetched at build time, cached forever
	const res = await fetch("https://api.example.com/products", {
		cache: "force-cache",
	});

	const products = await res.json();

	return (
		<div>
			<h1>Our Products</h1>
			<div className="grid">
				{products.map((product) => (
					<div key={product.id}>
						<h2>{product.name}</h2>
						<p>${product.price}</p>
					</div>
				))}
			</div>
		</div>
	);
}
```

**What happens:**

1. During build: Data fetched once
2. HTML generated with product data
3. Cached and served to all users
4. Lightning fast page loads

### 🔄 Part 3: Method 2 - Server-Side Rendering (SSR)

#### **What is SSR?**

**Definition:**

> Server-Side Rendering fetches data on every request. Each user gets fresh data rendered on the server.

---

#### **How It Works:**

```
User Request:
  ↓
Server receives request
  ↓
Fetch fresh data from API
  ↓
Render HTML with data
  ↓
Send HTML to user
  ↓
(Repeat for every request)
```

---

#### **Implementation:**

```typescript
// app/dashboard/page.tsx
export default async function DashboardPage() {
	// Dynamic fetch - no cache
	const res = await fetch("https://api.example.com/user/data", {
		cache: "no-store", // Fetch on every request
	});

	const userData = await res.json();

	return (
		<div>
			<h1>Welcome, {userData.name}</h1>
			<p>Last login: {userData.lastLogin}</p>
		</div>
	);
}
```

---

#### **Characteristics:**

**Performance:**

- ⚠️ Slower than SSG (server processing on each request)
- ⚠️ Can't be cached on CDN
- ⚠️ Server must process every request

**Data Freshness:**

- ✅ **Always fresh** - fetched per request
- ✅ User-specific data
- ✅ Real-time updates

**When It Happens:**

- ✅ On every user request
- ✅ Server processes each time
- ✅ Fresh data guaranteed

---

#### **When to Use SSR:**

**✅ Perfect for:**

1. **Personalized Dashboards**

```typescript
// app/dashboard/page.tsx
export default async function Dashboard() {
	// User-specific data - must be fresh
	const userData = await fetch("https://api.example.com/user/dashboard", {
		cache: "no-store",
	});

	return <UserDashboard data={userData} />;
}
```

- Different for each user
- Needs to be current
- Can't be cached

---

2. **Real-Time Data**

```typescript
// app/stock-prices/page.tsx
export default async function StockPrices() {
	// Stock prices change constantly
	const prices = await fetch("https://api.example.com/stocks", {
		cache: "no-store",
	});

	return <StockList prices={prices} />;
}
```

- Data changes frequently
- Freshness is critical
- Can't use stale data

---

3. **User-Specific Content**

```typescript
// app/profile/page.tsx
export default async function ProfilePage() {
	// User's profile data
	const profile = await fetch("https://api.example.com/profile", {
		cache: "no-store",
		headers: {
			Authorization: `Bearer ${token}`,
		},
	});

	return <Profile data={profile} />;
}
```

- Unique to each user
- Privacy concerns
- Must be fresh

---

#### **Automatic SSR Triggers:**

**Your route becomes dynamic (SSR) automatically when you:**

1. **Read Cookies**

```typescript
import { cookies } from "next/headers";

export default async function Page() {
	const cookieStore = await cookies();
	const token = cookieStore.get("token");

	// This route is now dynamic (SSR)
	return <div>Token: {token}</div>;
}
```

2. **Read Headers**

```typescript
import { headers } from "next/headers";

export default async function Page() {
	const headersList = await headers();
	const userAgent = headersList.get("user-agent");

	// This route is now dynamic (SSR)
	return <div>User Agent: {userAgent}</div>;
}
```

3. **Use Search Params**

```typescript
export default async function Page({ searchParams }) {
	const query = searchParams.q;

	// This route is now dynamic (SSR)
	return <div>Search: {query}</div>;
}
```

**Why?**

- These values are different per request
- Can't be determined at build time
- Must be rendered on the server per request

---

#### **Example: Dynamic User Dashboard**

```typescript
// app/dashboard/page.tsx
import { cookies } from "next/headers";

export default async function DashboardPage() {
	// Get user token from cookies
	const cookieStore = await cookies();
	const token = cookieStore.get("auth-token");

	// Fetch user-specific data (no cache)
	const res = await fetch("https://api.example.com/user/dashboard", {
		cache: "no-store",
		headers: {
			Authorization: `Bearer ${token?.value}`,
		},
	});

	const userData = await res.json();

	return (
		<div>
			<h1>Welcome back, {userData.name}!</h1>
			<div>
				<p>Account Balance: ${userData.balance}</p>
				<p>Last Login: {userData.lastLogin}</p>
				<p>Notifications: {userData.notifications.length}</p>
			</div>
		</div>
	);
}
```

**What happens:**

1. User requests page
2. Server reads cookies
3. Fetches fresh user data
4. Renders HTML with current data
5. Sends to user
6. Repeats for every request

### ⚡ Part 4: Method 3 - Incremental Static Regeneration (ISR)

#### **What is ISR?**

**Definition:**

> ISR combines static generation with periodic updates. Pages are static but regenerate in the background after a specified time.

---

#### **How It Works:**

```
Build Time:
  ↓
Generate static page
  ↓
User Request (within revalidate time):
  ↓
Serve cached static page (fast!)
  ↓
User Request (after revalidate time):
  ↓
Serve cached page (still fast!)
  ↓
Trigger background regeneration
  ↓
Next user gets fresh page
```

---

#### **Implementation:**

```typescript
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
	// Revalidate every hour (3600 seconds)
	const res = await fetch(`https://api.example.com/posts/${params.slug}`, {
		next: { revalidate: 3600 }, // Revalidate every 1 hour
	});

	const post = await res.json();

	return (
		<article>
			<h1>{post.title}</h1>
			<div>{post.content}</div>
		</article>
	);
}
```

---

#### **Characteristics:**

**Performance:**

- ⚡ **Fast like SSG** - serves cached HTML
- ⚡ CDN-friendly
- ⚡ No server processing for most requests

**Data Freshness:**

- ✅ **Periodically fresh** - updates in background
- ✅ Stale data for short periods
- ✅ Automatic regeneration

**When It Happens:**

- ✅ Initial build (like SSG)
- ✅ Background regeneration after revalidate time
- ✅ Transparent to users

---

#### **The Revalidation Flow:**

**Example: `revalidate: 3600` (1 hour)**

```
Time 0:00 - Build
  ↓
Page generated and cached

Time 0:30 - User A visits
  ↓
Serves cached page (fast!)

Time 1:15 - User B visits (after 1 hour)
  ↓
Serves cached page (still fast!)
  ↓
Triggers background regeneration
  ↓
New version generated

Time 1:20 - User C visits
  ↓
Serves NEW cached page
```

**Key Points:**

- First user after revalidate time gets old page
- Background regeneration happens
- Next users get fresh page
- No user waits for regeneration

---

#### **When to Use ISR:**

**✅ Perfect for:**

1. **Blog Posts**

```typescript
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
	const post = await fetch(`https://cms.example.com/posts/${params.slug}`, {
		next: { revalidate: 3600 }, // Revalidate every hour
	});

	return <Article post={post} />;
}
```

- Content doesn't change often
- Comments might be added
- Views/likes might update
- Don't need instant updates

---

2. **Product Pages**

```typescript
// app/products/[id]/page.tsx
export default async function ProductPage({ params }) {
	const product = await fetch(`https://api.example.com/products/${params.id}`, {
		next: { revalidate: 600 }, // Revalidate every 10 minutes
	});

	return <ProductDetail product={product} />;
}
```

- Price might change
- Stock might update
- Reviews might be added
- 10-minute delay acceptable

---

3. **News Articles**

```typescript
// app/news/[id]/page.tsx
export default async function NewsArticle({ params }) {
	const article = await fetch(`https://api.example.com/news/${params.id}`, {
		next: { revalidate: 300 }, // Revalidate every 5 minutes
	});

	return <NewsContent article={article} />;
}
```

- Breaking news updates
- Comment counts change
- Related articles update
- 5-minute delay acceptable

---

#### **Choosing Revalidate Time:**

**Common intervals:**

```typescript
// 1 minute - frequently changing
{
	next: {
		revalidate: 60;
	}
}

// 5 minutes - moderate changes
{
	next: {
		revalidate: 300;
	}
}

// 10 minutes - occasional changes
{
	next: {
		revalidate: 600;
	}
}

// 1 hour - infrequent changes
{
	next: {
		revalidate: 3600;
	}
}

// 1 day - rare changes
{
	next: {
		revalidate: 86400;
	}
}
```

**Guidelines:**

- Shorter = fresher data, more regenerations
- Longer = better performance, staler data
- Balance based on your needs

---

#### **Example: Blog with ISR**

```typescript
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
	// Fetch post with 1-hour revalidation
	const res = await fetch(`https://api.example.com/posts/${params.slug}`, {
		next: { revalidate: 3600 },
	});

	const post = await res.json();

	// Fetch comments with 5-minute revalidation
	const commentsRes = await fetch(
		`https://api.example.com/posts/${params.slug}/comments`,
		{
			next: { revalidate: 300 },
		}
	);

	const comments = await commentsRes.json();

	return (
		<article>
			<h1>{post.title}</h1>
			<div>{post.content}</div>

			<section>
				<h2>Comments ({comments.length})</h2>
				{comments.map((comment) => (
					<div key={comment.id}>{comment.text}</div>
				))}
			</section>
		</article>
	);
}
```

**What happens:**

- Post content revalidates every hour
- Comments revalidate every 5 minutes
- Different revalidation times for different data
- Optimal balance of performance and freshness

### 📊 Part 5: Comparison Table

#### **Complete Comparison:**

| Feature            | SSG                    | SSR                 | ISR                       |
| ------------------ | ---------------------- | ------------------- | ------------------------- |
| **Syntax**         | `cache: 'force-cache'` | `cache: 'no-store'` | `next: { revalidate: N }` |
| **When Fetched**   | Build time             | Every request       | Build + periodic          |
| **Performance**    | ⚡⚡⚡ Fastest         | ⚠️ Slower           | ⚡⚡ Fast                 |
| **Data Freshness** | ❌ Stale               | ✅ Always fresh     | ⚡ Periodically fresh     |
| **CDN Cacheable**  | ✅ Yes                 | ❌ No               | ✅ Yes                    |
| **Server Load**    | ✅ Minimal             | ⚠️ High             | ✅ Low                    |
| **User Wait Time** | ⚡ Instant             | ⚠️ Waits for fetch  | ⚡ Instant                |

---

#### **Use Case Matrix:**

| Content Type    | Recommended Method | Reason               |
| --------------- | ------------------ | -------------------- |
| Marketing pages | SSG                | Static, same for all |
| Product catalog | SSG or ISR         | Relatively stable    |
| Blog posts      | ISR                | Updates occasionally |
| User dashboard  | SSR                | User-specific        |
| Real-time data  | SSR                | Must be current      |
| Documentation   | SSG                | Rarely changes       |
| News articles   | ISR                | Updates periodically |
| Shopping cart   | SSR                | User-specific        |
| Product details | ISR                | Price/stock updates  |
| Search results  | SSR                | Query-specific       |

### 🎯 Part 6: Decision Framework

#### **How to Choose:**

**Ask these questions:**

1. **Is the data the same for all users?**

   - YES → Consider SSG or ISR
   - NO → Use SSR

2. **Does the data change frequently?**

   - NO → Use SSG
   - SOMETIMES → Use ISR
   - YES → Use SSR

3. **Is instant freshness critical?**

   - YES → Use SSR
   - NO → Use SSG or ISR

4. **Can you tolerate stale data for a period?**
   - YES → Use ISR
   - NO → Use SSR

---

#### **Decision Tree:**

```
Start
  ↓
Is data user-specific?
├─ YES → SSR
└─ NO
    ↓
    Does data change?
    ├─ NEVER → SSG
    ├─ RARELY → SSG
    ├─ SOMETIMES → ISR
    └─ FREQUENTLY → SSR
```

### 💡 Part 7: Best Practices

#### **1. Default to Static (SSG)**

```typescript
// Start with static
const data = await fetch(url); // Default is cache: 'force-cache'

// Only opt into dynamic when needed
```

#### **2. Use ISR for Most Dynamic Content**

```typescript
// ISR is often the sweet spot
const data = await fetch(url, {
	next: { revalidate: 3600 },
});
```

#### **3. Reserve SSR for Truly Dynamic Content**

```typescript
// Only use no-store when absolutely necessary
const data = await fetch(url, {
	cache: "no-store",
});
```

#### **4. Mix Strategies in One Page**

```typescript
export default async function Page() {
	// Static data
	const staticData = await fetch(url1, { cache: "force-cache" });

	// ISR data
	const isrData = await fetch(url2, { next: { revalidate: 600 } });

	// Dynamic data
	const dynamicData = await fetch(url3, { cache: "no-store" });

	return <Component data={{ staticData, isrData, dynamicData }} />;
}
```
